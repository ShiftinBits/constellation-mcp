## Root Cause: Missing CALLS Edges

The most serious finding. Traced end to end through the real pipeline and confirmed
reproducible on a clean full re-index.

### Symptom

Functions with many real call sites report zero callers. `getCallGraph({direction:
'incoming'})` returns `callerCount: 0` for a function called six times. This is a
confidently wrong answer, not an empty result.

### What was eliminated

Each of these was tested directly, not inferred:

| Stage                 | Method                                                                                     | Result                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| CLI parse + serialize | Ran the real `serializeAST` over the real 49KB `sandbox.ts`                                | All 193 call nodes serialized with callee identifier text intact        |
| Core extraction       | Replayed the serialized tree through `wrapSerializedNode` + the real `TypeScriptExtractor` | 16 rows for `createStructuredError`, 128 for `enrichWithSourceSnippets` |
| Call shape            | Matrix of bare/member callee × single/multi-line args × inside `try`/`catch`               | All shapes captured correctly                                           |
| Scope attribution     | Nested arrow callbacks                                                                     | Correctly attributed to the enclosing named symbol                      |
| P1/P2 routing         | `relationship-batcher.service.ts:509`                                                      | All callees route identically to the P2 cross-file path                 |
| Target ambiguity      | Candidate count per callee                                                                 | Each resolves to exactly one unique exported symbol                     |
| Incremental staleness | Clean `constellation index --full`                                                         | Reproduces exactly                                                      |

### Root cause

Instrumenting `Pass2OrchestratorService.runCallsPair` to dump every row entering the
P2 fallback produced a perfect correlation:

| Callee                     | Rows with real caller id | Rows with `global` | Graph result |
| -------------------------- | ------------------------ | ------------------ | ------------ |
| `validateAst`              | 1                        | 60                 | 1 CALLS edge |
| `addAutoReturn`            | 1                        | 36                 | 1 CALLS edge |
| `getProjectCapabilities`   | 1                        | 23                 | 1 CALLS edge |
| `createStructuredError`    | **0**                    | 64                 | **none**     |
| `enrichWithSourceSnippets` | **0**                    | 11                 | **none**     |

Two defects compound:

1. **Extractor loses the enclosing scope.** `typescript-extractor.ts:1584` builds rows
   with `callerId: currentScope || 'global'`. When `getCurrentScope()` returns empty it
   emits the sentinel string `global`. In this project 8669 P2 rows were produced and
   the overwhelming majority carry that sentinel (194 of 197 rows in the watched sample).

2. **The graph write discards them silently.** The P2 template opens with a
   non-optional match (`pass2-templates.ts:1245`):

   ```cypher
   MATCH (caller:Symbol {id: call.callerId, ...})
   ```

   No symbol has id `global`, so the row yields nothing. Both `FOREACH` branches — the
   one that creates the `CALLS` edge (line 1279) and the one that stages an
   `UnresolvedCall` for forensics (line 1291) — sit downstream of that match, so the row
   produces no edge _and_ no diagnostic record.

A call site therefore survives only if at least one of its duplicated rows happens to
retain a real scope id, which is why the pattern looked arbitrary.

### Second failure mode

`getDefaultConfig` (TC-TRACE-001) fails differently: its call rows _do_ reach the graph
and stage an `UnresolvedCall` node, but the later promotion passes never convert it to a
`CALLS` edge even though the target exists as an exported method in the same project.
Modes A (row discarded before staging) and B (staged but never promoted) are distinct
and both need fixing.

### Scale

The project holds roughly 108 CALLS edges per index generation despite containing 137
methods and 101 functions. Most call rows never survive the caller match, so call-graph
answers are broadly under-populated rather than occasionally wrong.

### Not fully isolated

Why `getCurrentScope()` returns empty for `sandbox.ts:602` but not `sandbox.ts:1401`
was not determined. Every structural difference reproduced in isolation retained scope
correctly.

## Other Defects

### Object literals extracted as anonymous `class` symbols

35 of the 65 `class` nodes are named `<anonymous@line:col>`. Verified against source:
`dangerous-patterns.ts:109` and `:126` are entries in a `PatternChecker[]` array
literal; `tsup.config.ts:4` and `:27` are config objects passed to `defineConfig`.
These are object literals, not classes. Query results are unaffected because the API
filters anonymous-named symbols (class searches return 30 while `function` 101 and
`method` 137 match Neo4j exactly), but the stored graph misrepresents the code and this
is the sole cause of the TC-DISC-012 count gap.

### Pattern checkers match inside string literals

The regex sweep that runs ahead of the parse-based validator does not distinguish code
from string contents, so any script mentioning `process.`, `eval(`, or `require(` in a
string or comment is refused. Demonstrated by TC-ERR-007. The parse-based validator
handles this correctly.

### `filterByKind` accepts unknown values silently

`filterByKind: ['bogusKind']` returns an empty result set with no error, while
`direction: 'sideways'` correctly fails with an enum validation error. A typo yields a
plausible-looking empty answer instead of a validation failure.

### Call-row inflation

The extractor emits 3416 call rows for 193 call sites in one file (~17x). The factor
tracks nesting depth as a power of two (8 rows for shallow calls, 128 for the deeply
nested `enrichWithSourceSnippets`), suggesting repeated subtree traversal. Every call
site also emits one row with the unusable `global` caller id.

## Procedure Staleness (not product defects)

- **Case sensitivity.** The procedure states the Core executor uses case-sensitive
  `CONTAINS` and instructs validators not to use `toLower()`. No longer true. `query: 'e'`
  returned 2510 against case-sensitive Cypher 2413 and case-insensitive 2510. The
  exported variant matched the same way (API 140, case-sensitive 92, case-insensitive
  140). Both TC-XVAL-001 and TC-XVAL-006 pass against case-insensitive ground truth.
- **`listMethods()` count.** Now 14, not 12 (TC-CODE-014, TC-CODE-018).
- **Weak Neo4j proxies.** Several validation queries diverge from the API for reasons
  that are query artifacts: depth traversals filter on `:File` and exclude `Package`
  targets; `count(dependent)` without `DISTINCT` inflates counts; the impact query walks
  `(File)-[:CONTAINS]->(ref)` and misses references originating from `File` nodes (7 of
  9 for `ConstellationClient`).
- **Cycle rotations.** `findCircularDependencies` reports 1 cycle where the procedure's
  Cypher reports 2 — the same two-file cycle traversed from each member. The API's
  deduplication is correct.

## Retracted Finding

An earlier draft flagged duplicate index generations (6056 symbol nodes for 3028
distinct ids) as a possible leak. **This is not a defect.** Generational writes with a
delayed sweep are the intended design. The reconciliation cron's `graph_attempt_orphan`
pass deletes non-active generations directly, runs every 30 minutes, and skips attempts
inside a 1-hour grace window (`RECONCILE_GRACE_MS`). The generations observed were
simply inside that window.

## Vacuous Passes

TC-DISC-005 passes because API `usageCount: 0` matches Neo4j `usageCount: 0` for
`getDefaultConfig` — but the true answer is five call sites. Any cross-validation test
whose ground truth is the same graph it is validating will agree with itself. Tests that
assert only API/Neo4j agreement cannot detect extraction or resolution defects; several
call-graph assertions in the procedure have this shape.
